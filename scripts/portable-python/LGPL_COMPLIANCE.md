# Portable Python Guest Image — LGPL-3.0 Distribution Compliance & Relink Guide

## 1. Scope & Separate Guest-Library Distribution

The Portable Python WASI guest image (`portable-python-image-pyc.tar.gz`) is distributed separately from host-side separate binary distributions (such as Git and OpenGrep). Within the immutable guest image, two pure-Python libraries are licensed under the GNU Lesser General Public License v3:

| Distribution | Version | License | Upstream Source Archive | Upstream Source SHA-256 | Local Patches |
| --- | --- | --- | --- | --- | --- |
| `fpdf2` | `2.9.0` | `LGPL-3.0-only` | `fpdf2-2.9.0.tar.gz` | `af2e7e06a5a2f9e32e24b146b56f58166142dfff45f55370ab03bfac9c8e3e21` | `packages/fpdf/image_parsing.py` (fail-closed WASI URL-loader refusal) |
| `pygal` | `3.1.3` | `LGPL-3.0-or-later` | `pygal-3.1.3.tar.gz` | `dd119c14cdeb56beb85282e3e2687ece30561225d410a822e6bb68699aa6e7b1` | None |

`yamllint` (`GPL-3.0-or-later`) is **omitted** from the distributed guest image.

## 2. Source Availability & Compliance Pack Contents

Every release distributing a Portable Python image containing `fpdf2` and/or `pygal` includes the corresponding LGPL compliance pack generated by:

```bash
python3 scripts/portable-python/build-lgpl-compliance-pack.py \
  --lock scripts/portable-python/lock.json \
  --bundled-manifest lycaon/config/runtime/portable-python/bundled-manifest.yaml \
  --cache-dir ~/.cache/pw-py11-build \
  --out-dir results/PY11/lgpl-compliance/pack
```

The compliance pack contains:
- `sources/fpdf2/fpdf2-2.9.0.tar.gz` + extracted `LICENSE` and copyright notices
- `sources/pygal/pygal-3.1.3.tar.gz` + extracted `COPYING` and copyright notices
- `patches/fpdf2-image_parsing.patch` — exact unified diff of the local WASI compatibility patch applied to `fpdf/image_parsing.py` (replacing absent WASI `_ssl` HTTPS classes with fail-closed refusing stubs and explicitly refusing remote URL image loads with `FPDFResourceAccessError`)
- `build-scripts/` — `build-image.py`, `image_assets.py`, `lock.json`, `stage-bundled.sh`, `LGPL_COMPLIANCE.md`, `bundled-manifest.yaml`
- `THIRD_PARTY_NOTICES.txt` — reconciled closure of all distributions, transitive dependencies, bundled fonts, native WASI libraries, and LGPL guest-library notices
- `reconciliation-report.json` — automated verification that every `.dist-info` distribution, resource, font, and transitive license in the staged image matches `THIRD_PARTY_NOTICES.txt` and `image-manifest.json`
- `SHA256SUMS` — cryptographic digests for every file in the compliance pack

## 3. Recipient Instructions: Modify, Rebuild, Re-Pair, and Run

Under LGPL-3.0 Sections 4(d) and 4(e), a recipient may modify `fpdf2` or `pygal`, rebuild the Portable Python guest image, pair it with the matching native engine, and run their own product build:

### Step 1: Modify the LGPL Library
1. Unpack the corresponding upstream source archive (`fpdf2-2.9.0.tar.gz` or `pygal-3.1.3.tar.gz`) and apply your modifications (for `fpdf2`, preserve the WASI `image_parsing.py` compatibility patch if running in `wasm32-wasi`).
2. Build a pure-Python wheel from your modified source tree (`python3 -m pip wheel --no-deps --no-build-isolation -w /tmp/custom-wheels .`).
3. Compute its SHA-256 (`sha256sum /tmp/custom-wheels/*.whl`) and update the corresponding `filename`, `source_sha256`, and `source_url` (or place the wheel in `--cache-dir/packages/`) in `scripts/portable-python/lock.json`.

### Step 2: Rebuild the Deterministic Checked-Hash `.pyc` Image
Run `build-image.py` against the matching WASI CPython interpreter archive (`python-3.12.0-wasi-py10.tar.gz`, same `v0.2.0` engine):

```bash
SOURCE_DATE_EPOCH=1764201600 python3 scripts/portable-python/build-image.py \
  --lock scripts/portable-python/lock.json \
  --cache-dir /tmp/custom-cache \
  --out-dir /tmp/custom-image-out \
  --interpreter-archive /path/to/python-3.12.0-wasi-py10.tar.gz \
  --with-pyc \
  --pyc-python /path/to/python3.12
```

Rename `portable-python-image.tar.gz` to `portable-python-image-pyc.tar.gz` and record the new `image_id`, `archive_sha256`, `archive_bytes`, `manifest_sha256`, `packages_tree_sha256`, and `pyc_tree_sha256` from `/tmp/custom-image-out/image-manifest.json`.

### Step 3: Re-Pair Your Product Build (Why Stock Rejects Mixed Identities)
The stock Painted Wolf binary verifies the staged image against the exact digests pinned in `lycaon/config/runtime/portable-python/bundled-manifest.yaml`. If a modified image is substituted into an **unmodified stock product** without updating the manifest, staging and runtime verification **fail closed** with a digest/identity mismatch.

To run your modified LGPL library in your own product build:
1. Update the `portable_python_image` fields in `lycaon/config/runtime/portable-python/bundled-manifest.yaml` with the new digests from Step 2 (keeping the `portable_python_engine` `v0.2.0` section unchanged).
2. Stage the paired engine and rebuilt image:
   ```bash
   PW_PORTABLE_PYTHON_IMAGE_ARCHIVE=/tmp/custom-image-out/portable-python-image-pyc.tar.gz \
     scripts/portable-python/stage-bundled.sh --root /tmp/custom-stage
   ```
3. Build and run your product binary (`CGO_ENABLED=1`) pointing at `/tmp/custom-stage/portable-python`.

## 4. Automated Relink & Mixed-Identity Rejection Proof

Use `build-lgpl-compliance-pack.py --relink-demo` to reproduce both halves of the LGPL relink verification on macOS arm64 and Linux amd64:
1. **Harmless visible change:** Injects a harmless visible marker into `fpdf2` and `pygal`, rebuilds the `.pyc` image, updates a temporary `bundled-manifest.yaml`, stages, and runs the packaged tool to confirm both the PDF (`fpdf2`) and SVG (`pygal`) outputs contain the visible marker.
2. **Stock-product mixed-identity rejection:** Attempts to stage/verify the modified image against the unmodified stock `bundled-manifest.yaml` and confirms non-zero fail-closed rejection.

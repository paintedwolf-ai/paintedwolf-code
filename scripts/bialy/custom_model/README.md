# Custom coordinator training

This is the offline custom-model pipeline. Decision-head training keeps its
existing scripts and row contract. These scripts do not install models, upload
artifacts, launch teachers, or start provider-backed collection.

## Capture and admission

A training row pairs the request the student will be served with the response
a student should emit, and every rule below follows from that.

Capture runs only when `PW_TRAINING_CAPTURE_DIR` (an existing private absolute
directory), `PW_TRAINING_EPOCH`, `PW_TRAINING_STUDENT_PROVIDER` and
`PW_TRAINING_STUDENT_MODEL` are all set on the isolated host. The student
provider is a configured provider entry describing how the student will be
served, with its model's `context_length`; collections declare it but never
drive it. The Bialy runner writes that entry and creates the directory inside
its shard.

`pw-training-turn/1` records, per settled model output:

- the exact teacher dispatch, as provenance;
- the request rendered offline through the student's provider entry
  (`Registry.RenderRequest` with the adapter's `RequestRenderer`), as training
  input. It is rendered from the request the adapter serialized, after every
  host projection and screen, so it carries the student's own message layout.
  A request the student could not be served, such as one over its declared
  window, is excluded as `student_cannot_be_served`;
- the target. When the host changed only what a student never emits (call
  identifiers, duplicate or argument-less sibling calls it removed), the target
  is the settled message, because the receipts name the settled calls; the
  changes are listed in `normalized`. A change to content, a call name or its
  arguments excludes the turn and names the field in `modified_fields`.

A request message the durable transcript policy would change is excluded as
`transcript_policy_changes_request`, with its position: training artifacts
persist only what the host's transcript would. Reasoning-bearing, failed,
scripted, unsettled and retried attempts are excluded by name. Exclusions keep
identifiers and field names only. When the host commits a tool-free reply as a
turn's visible result it writes a `pw-training-fact/1` `turn_committed` fact,
which is the acceptance evidence for that reply. Files use mode 0600 and atomic
publication. This is an experimental collection artifact, not a database or
public API change.

`collect.py` reads immutable shard snapshots and actual invocation receipts. It
decodes the student request into the chat-template input that the student's
server builds. Only `openai-compatible` qualifies: llama.cpp's server with
`--jinja` applies the checkpoint's own template, after deserializing tool-call
arguments into objects as Gemma 4's template requires. Ollama renders prompts
with its own templates, whose parity with the checkpoint is not established.
Every tool call must match a completed, invoked receipt by session, message,
call ID, tool name and canonical arguments. A tool-free reply must be the output
the host committed. Floating-point arguments, multimodal inputs and unsupported
controls fail closed, and every exclusion is counted by its reason.

On the `command-v1` surface a `command` call is admitted only when its child
operation receipts all settled with known effects; a program that left partial
or unknown effects, a whole-program replay of such a program, or a store without
child receipts fails closed (`command_contract.py`, written against the P32 and
P33 contracts; its table and column names are the adaptation point when those
receipts are persisted). The legacy surface admits command receipts like any
other tool's.

Teacher servers must run with thinking disabled (llama-server
`--reasoning-budget 0`) and without context shift: a reply that carries
reasoning is excluded, and a shifted context would record a prompt the model
never saw.

The exported `pw-model-request-capture/2` retains generation controls as well as
messages and schemas. Its state digest binds the observed request and settled
attempt; it is **not** a replayable filesystem or external-service snapshot.
No same-state counterfactual DPO labels are generated by this exporter. Later
recovery turns and teacher repairs remain proposals. The DPO trainer accepts
separately validated same-request pairs; this does not supply their validation.

Acceptance and quality remain separate. Bialy's explicit `dpo quality` operation
or `custom_model.quality_judge: true` reviews the exact request/response and
subsequent evidence with another model family. That operation makes model calls.
It binds every verdict to request, response, source evidence and model revisions.
Without a passing quality report, the response remains a candidate. The factory
also requires nonempty train, validation and held-out splits before marking SFT
inputs consumable. Stable `split_group` lineage spans workers and epochs.

## Training and recovery

Use the locked environment with `uv run --project scripts/bialy/custom_model
--locked python ...`. Training takes materialized local checkpoint directories,
with no symlinks, remote model downloads, or remote-code execution. Pin the model
and tokenizer by complete file inventories. Start with SFT; DPO starts from the
merged SFT checkpoint and uses that identical frozen reference.

A bounded pilot command, after qualified datasets and local model files exist:

```sh
uv run --project scripts/bialy/custom_model --locked python scripts/bialy/custom_model/train.py \
  --mode sft --model /scratch/models/student \
  --train /scratch/data/train.jsonl --validation /scratch/data/val.jsonl \
  --holdout /scratch/data/holdout.jsonl --out /scratch/runs/student-sft \
  --device cuda:0 --targets q_proj,v_proj --max-length 8192 \
  --max-updates 20 --max-seconds 3600 --checkpoint-every 10
```

`--targets` takes module names or `re:<regex>` over full module paths. Gemma 4
checkpoints load as the multimodal `Gemma4ForConditionalGeneration`, so anchor
the pattern to the language model, for example
`re:.*language_model.*\.(q_proj|k_proj|v_proj|o_proj)`. Logits are computed
only at positions that predict a completion token (`logits_to_keep`); a
full-vocabulary log-softmax over 8,192 positions of a 262,144-token vocabulary
would need about 21 GB by itself. Do not shorten an accepted request to fit.
The tokenizer must preserve the full generation prefix and every target;
oversize or unsupported rows stop preparation with an error. Prompt tokens are
masked. DPO uses summed completion log likelihoods with a frozen reference;
the optional chosen NLL anchor is token-normalized.

Resume with the same arguments and `--resume`. Change only the per-invocation
wall-time/update limits and checkpoint cadence/retention. Model, dataset,
objective, optimizer, package and implementation identities must still match.
A POSIX process lock prevents two writers and releases automatically on a crash.

- Atomic checkpoints include adapter, optimizer, epoch and row position,
  partial validation progress, and Python/Torch/CUDA RNG state. Three are retained
  by default; at least two are required. Disk headroom is checked before writes.
- SIGINT/SIGTERM pause after the current update. A hard crash can lose at most
  the updates since the last completed checkpoint. An interrupted write never
  replaces a complete checkpoint; a corrupt newest checkpoint falls back to the
  previous verified one and is reported.
- Reference scores commit individually to SQLite, keyed by full tokens, masks,
  reference and template identity. Resume reuses verified entries and checks a
  fresh score. Reference and policy models load sequentially.
- `progress.json` reports measured update duration, its observed range, remaining
  training-time estimate, peak process RAM and CUDA allocation. The estimate
  explicitly excludes other stages. `--max-seconds` is checked between operations,
  not a hard deadline inside a model forward pass or filesystem operation.
- A result is complete only when `result.json` exists and its adapter hashes
  verify. A paused pilot is not a completed training artifact.

Keep checkpoints on the training host's local disk; copy completed checkpoints
and input manifests to separate storage between sessions. Resume is crash recovery,
not protection against losing the entire disk. Reclaimed disk does not increase
VRAM, and Q4 inference fit does not establish training-memory fit.

## Export

`export.py --model BASE --run TRAINING_RUN --out NEW_DIRECTORY` checks all source
hashes, safely merges the adapter, verifies logits before/after the merge, saves a
new safetensors checkpoint, and reloads it for parity. It frees the merged model
before loading the saved copy. Use `--resume` to verify and reuse the saved
merge after an interrupted reload or publication. Existing stock weights remain
untouched.

`gguf_export.py --merge MERGED_DIRECTORY --llama-cpp PINNED_CHECKOUT --revision
FULL_COMMIT --quantizer ABSOLUTE_BINARY --loader ABSOLUTE_LLAMA_CLI --out
NEW_DIRECTORY` converts to F16 and then Q4_K_M. Both artifacts are inventoried by
tensor name, shape, type, range and content hash. Tokenizer/template metadata and
unquantized tensor bytes must survive quantization. A load-only probe generates
zero tokens. Use `--resume` to reuse verified conversion/quantization stages
following an interruption. Completed exports are immutable; corruption requires
a new output directory. Build/binary identities are recorded; endpoint readiness
or a binary filename alone does not prove build provenance.

These parity checks do not establish production behavior. Qualify the actual
quantized artifact on held-out tasks and target hardware before promotion.

## Offline contracts

```sh
uv run --project scripts/bialy/custom_model --locked python -m unittest discover \
  -s scripts/bialy/custom_model -p 'test_*.py'
```

The fixtures use SQLite, a tiny randomly initialized local model, and fake export
commands. They never download pretrained weights or contact a provider. They cover
receipt binding, masks, reference gradients, split separation, pause/resume,
corrupt-checkpoint fallback, cache recovery, SFT/DPO, merge/reload and export-stage
recovery. Production-model memory, speed and GGUF conversion remain live gates.

The existing prompt loop retains request/settlement authority. Its 559-line
baseline exceeded the warning threshold but was below the 900-line hard limit;
the capture hooks add six lines and no new service methods. Serialization,
privacy and file lifecycle live in `internal/trainingcapture`, keeping the
settlement transaction in its existing owner. The focused capture and wire tests
support this bounded retention; no budget limit is raised.

Implementation references: [Transformers chat templates](https://huggingface.co/docs/transformers/chat_templating),
[PEFT LoRA](https://huggingface.co/docs/peft/package_reference/lora), and the pinned
[llama.cpp converter](https://github.com/ggml-org/llama.cpp/blob/master/convert_hf_to_gguf.py).

Collection runners also consume `pw-training-health/1` artifacts from the capture
directory. These contain only the epoch, utility purpose, success, protocol finish
reason and timestamp. They let a runner stop after repeated truncated compaction
summaries without parsing provider error prose or capturing utility payloads. The
receipt exporter ignores them; they are diagnostic evidence, never training rows.

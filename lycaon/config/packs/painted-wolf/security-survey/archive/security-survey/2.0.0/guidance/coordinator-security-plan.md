Decompose the user's security ask into a threat model, then a falsification-oriented fan-out, before any workers run. The host has already collected the security scans bound to this run. Do not run `scan_pack` for this pack and do not `wait(scan_done)`.

1. Take the survey-ladder first move (named area → **`summarize(path=…)`**; cannot name a destination and a matching bundle → **`survey_repo`**). Read `SECURITY.md`, deploy docs, or auth/entry-point code if they exist. Do **not** dispatch workers in this phase.
2. Orient on `obligations.scan.scan_ids` and `per_scan`; they are the exact run-bound set. Pass that array to `scan_summary` and `scan_query`. Do not call `scan_list` to rediscover scans or follow newer project-ambient work. Read execution and coverage status separately. Completed scans with partial coverage have usable results and disclosed limitations. A successful empty scan is a negative result, not proof of safety.
3. **State the target threat model before any legs.** Infer it from this repo — system kind (library, CLI, desktop app, local service, public HTTP API, …), who can reach it, and how authentication works. Do not assume a public web app. If the model is ambiguous and would change which surfaces matter, `ask_user` once; otherwise state the inference in `threat_model`.
4. Choose **1–{{ max_fanout_legs }}** non-overlapping legs from **that model's surfaces**, not a fixed checklist. Each leg is one adversary + one surface and a hypothesis to try to disprove. Require a trace from entry point through parsing, defaults, authentication/authorization, and the effectful sink; include constructors, alternate callers, error paths, and bypass routes. Names, comments, intended architecture, and a helper's existence are leads, not proof that every caller reaches enforcement. Legs grounded in scan results count toward the same cap. Every `agent_type` must be **`security-reviewer`**. Do **not** plan `skeptic` or `web-researcher` legs; those run later against claims. Default scope is read-only.
5. Size each leg's `max_tool_loops` to its ground. A leg that traces a whole subsystem, its alternate callers, and its error paths needs more rounds than the host default; a leg confined to a few files does not. A leg that still runs short can ask you for more rounds, so size for the expected trace rather than the worst case.
6. Call `fanout_plan` with `threat_model` and the legs, each with a `subject` a non-developer understands ("Desktop app"), and explicit `done_when` criteria for its trace and unresolved scope, then `workflow_advance` when `fanout_planned` is satisfied.

Ban these briefs: "identify any risks," "confirm the control works," "findings with severity reasoning," any brief that states an intended control as established before tracing all relevant callers, any generic web checklist, and any wrap of the user's original ask as a skeptic proposition. The host binds the stamped threat model and scan facts to planned workers.

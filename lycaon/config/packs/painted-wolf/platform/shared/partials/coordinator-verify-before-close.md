### Validation and closeout

Match checks to consequences and user/repository requirements. Inspection can establish non-executable material; target affected behavior and use project checks for broader or required coverage. A selected test command is a default check, not a full-suite mandate.

Wait on a running handle without duplicating it; only settled success passes. Listening and connecting require separate grants. Retry only after evidence-backed edits (three attempts maximum).

Record required validation and UI capture as explicit checklist work. For interface changes, exercise primary controls and capture the running result before closing. Tests and source inspection do not replace that observation. If execution is unavailable, report required validation as blocked; do not describe an unverified primary path as delivered. For non-executable changes, report inspection and its scope. Report checks, outcomes, and remaining limits.

## Worker chain

- Dispatch **enqueues** (`job_id`, `"enqueued"`) — host swaps completion envelope when done; enqueue JSON ≠ completion.
- Worker results arrive in the `<task …>` completion envelope (`report_json`, `proof_json`, summary), **not files** under `${overlay_dir}/`; do not look under project paths for them. Cross-cutting worker notes reach peers as **sibling notes** each turn. Present useful worker stills with `[artifact:<uuid>]`, only from `proof_json.visual_artifact_ids`.
- **Scope:** read scouts → `scope.mode: read`; mutation workers (**implementer**, **plan-writer**) → `scope.mode: write` + paths (host rejects read/default). **Workers start cold** — one isolated overlay per write leg (isolated workspace at dispatch); no sibling overlays, no live project tree mid-flight. Peer channel: sibling notes only. You integrate through overlay preview and promotion (host-applied to the project tree; never git) — never brief workers to read peer overlays or wait on peer file state.
- **Leg brief:** one focus per dispatch; use the bounded `brief` object — `goal`, material `known_facts`, `constraints`, concrete `done_when`, and compact `context_refs`. Keep items atomic and concise (≤500 chars each, max 6 items per field). Put likely paths in `files` and authority in `scope`; never "as discussed" — host injects worker file orientation. Workers do not see the parent chat, so carry only facts the leg cannot recover (artifact shape, naming conventions, compatibility bounds), never a pasted user message. **No telephone** — rewrite user/plan editorial into observable survey scope; never pass loaded adjectives (worst, bloated, rot, broken, critical) or pre-judged conclusions. Broad audits still name bounded source families or subtrees and an explicit stop condition. Do not use open-ended scope such as "any", "the rest of", whole-catalog inventory, or repository-wide absence unless exhaustive coverage is itself the deliverable; request representative evidence otherwise.
- **A write leg’s `done_when` names proportionate validation.** Carry user/repository requirements into the brief; allow inspection where sufficient. The selected check is a default, not a full-suite mandate. Workers report scope and limits; blocked validation alone does not require resuming completed work or prevent promotion.
- Up to **{{ max_in_flight }}** jobs in flight; cap → `Code: COORDINATOR_WORKER_IN_FLIGHT`.
- Continue coordinating ready work after dispatch. {% if profile_has_wait %}Use **`wait(timeout_ms=120000–300000, conditions=[{kind: next_worker_done}])`** when the next action needs a result. Choose `{kind: all_workers_idle}` only when you need the whole set.{% endif %}
- Wait for **complete** envelopes before user-facing done claims; `partial` → re-dispatch. Synthesis: restate worker **`findings[]`** or paths from your tool results — not **`brief`**/`objectives_met`.
- After a complete envelope, send your final answer before you read the board again (`Code: COORDINATOR_BATCH_WRONG_PHASE`).

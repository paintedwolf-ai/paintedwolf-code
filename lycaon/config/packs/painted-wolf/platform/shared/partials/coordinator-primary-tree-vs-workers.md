**Primary tree vs workers:** Read-scoped workers (`scope.mode: read`) survey the **primary** tree — they do not write it. Write-scoped workers edit **private views** landed by overlay promotion, not by restoring files. Primary-tree `git status` output is therefore **unrelated to worker completion** and never a reason to revert files.

**Coordinate before dispatch:** Give collaborators the same relevant interface agreements in the dispatch's shared context. Write workers cannot read one another’s modules; findings share text, not files. For integration against producer code, set `task.after_workers` to the producer job IDs. The host waits for successful results and write promotion before capturing the consumer snapshot. Unusable producer output cancels waiting consumers; dispatch replacements with repaired prerequisites. Resuming a child keeps its old snapshot; use a fresh worker to consume newly promoted files.

**Git on write legs:** Whether a write leg's view carries Git depends on the view; the leg's own frame states it. A leg that holds `source_history` has `source_history()` as its change overview and `source_history(path, mode=diff)` as its per-file diff. Reading the primary tree's history, or recovering a past revision of it, is a read-scoped leg or your own turn.

**Intermediate scratch:** Store working notes, raw tool dumps, and temporary scripts under `@scratch/`. Never create scratch files in the primary repository, as they dirty `git status` output for downstream work. Each worker's `@scratch` is its own private folder: what you need from a worker comes back in its result, not as a scratch path.

**Main tree vs workers:** Read-scoped workers (`scope.mode: read`) survey the **main** tree — they do not write it. Write-scoped workers edit **private views** landed by overlay promotion, not by restoring files. Main-tree `git status` output is therefore **unrelated to worker completion** and never a reason to revert files.

**Coordinate before dispatch:** Give collaborators the same relevant interface agreements in the dispatch's shared context. Write workers cannot read one another’s modules; findings share text, not files. For integration against producer code, set `task.after_workers` to the producer workers' names. The consumer waits until each producer has delivered a complete result and its changes landed. A producer that is closed, or whose changes are rejected, leaves its consumer waiting and raises a notice; start a replacement or withdraw it. A worker you send back keeps its own workspace across rounds; after its changes land, its next round starts from refreshed source.

**Git on write workers:** Whether a write worker's view carries Git depends on the view; the worker's own frame states it.{% if profile_has_source_history %} A worker that holds `source_history` has `source_history()` as its change overview and `source_history(path, mode=diff)` as its per-file diff.{% endif %} Reading the main tree's history, or recovering a past revision of it, is a read-scoped worker or your own turn.

**Intermediate scratch:** Store working notes, raw tool dumps, and temporary scripts under `@scratch/`. Never create scratch files in the main tree, as they dirty `git status` output for downstream work. Each worker's `@scratch` is its own private folder: what you need from a worker comes back in its result, not as a scratch path.
